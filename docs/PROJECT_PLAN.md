# 遇事不决问毛选：产品与开发方案

## 1. 产品定位

一个通过摄像头手势完成的语录抽卡应用。用户对着镜头左右挥手选择卡牌，收拢拇指与食指触发抽牌，翻开一张带出处的毛选语录作为"答案"。整个体验围绕"遇事不决问毛选"展开：问题不必输入，给出一张卡片，就是把一个问题交给一种朴素而坚定的方法论。

## 2. 技术选型

| 模块 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite 6 + React 18 + TypeScript | 启动快、类型安全、适合纯前端工具型应用 |
| 手势识别 | MediaPipe Hands（`@mediapipe/hands`） | 成熟的手部 21 关键点方案，可在浏览器本地推理 |
| 模型部署 | 模型与 wasm 复制进 `public/mediapipe-hands/` | 不依赖外网 CDN，避免 Google 模型地址在国内不可达的问题 |
| 图标 | lucide-react | 统一、轻量，配合工具栏和手势说明 |
| 样式 | 原生 CSS 变量 + 响应式布局 | 无额外框架开销，视觉细节可控 |
| 测试 | Vitest | 手势逻辑与数据是纯函数，测试成本低 |

无需后端。语录、牌库、抽牌历史都保存在浏览器内存中；未来如需同步，可加 IndexedDB 或轻量服务端。

## 3. 交互设计

### 3.1 核心状态机

1. `playing`：摄像头就绪或未开启，牌扇可见，用户浏览卡牌。
2. `drawing`：收到收拢手势后播放翻牌动画，禁止再次抽牌。
3. `result`：展示抽中的语录、出处与标签，可"再问一次"或收起。

### 3.2 手势映射

| 手势 | 判定规则 | 结果 |
| --- | --- | --- |
| 左划 | 掌心在约 320ms 窗口内向左位移超过阈值，水平位移显著大于垂直位移 | 下一张 |
| 右划 | 掌心向右位移超过阈值 | 上一张 |
| 收拢 | 拇指尖与食指尖距离与手掌尺寸之比低于阈值，且持续数帧 | 抽牌 |

所有手势都带冷却时间与连续帧确认，避免误触发。

### 3.3 降级交互

没有摄像头或权限被拒绝时，应用仍可完整游玩：

- 点击牌扇中的任意卡牌直接选中。
- 左右箭头按钮切换卡牌。
- 键盘 `←` `→` 切换，`Enter` / 空格抽牌，`Esc` 收起结果。

## 4. 视觉设计风格

视觉方向是"新中国印刷物 + 民间牌面"：宣纸米色为底，朱砂红做主色，墨色排印，金色做仪式点缀。不追求复制特定宣传画，而是提取它的印刷质感。

- 底色：暖纸色 `#f2e8d0`，配合细密横纹模拟纸张。
- 主色：朱砂红 `#b42318`，用于印章、边框、主按钮。
- 辅助色：墨黑 `#1f1e1a`、旧金 `#a97f2d`、深绿 `#2e5947`，避免整页只有红一种色相。
- 字体：正文用宋体系（Songti SC / Noto Serif SC），标题与语录用楷体系（Kaiti SC / KaiTi），强化书卷气。
- 布局：桌面端左侧摄像头、右侧牌扇；移动端上下堆叠。牌扇用扇形排布，选中牌立起。
- 反馈：翻牌动画、手势 toast、识别状态胶囊，保持短促明确。

## 5. 任务拆解

1. 项目初始化：Vite + React + TS + Vitest。
2. 媒体资源：下载/复制 MediaPipe Hands 模型与 wasm 到本地。
3. 语录数据：从公开文献与题词中整理 100 条语录，记录出处、原文选段、解读与标签。
4. 手势引擎：实现掌心轨迹、划动方向、收拢判定、冷却与防抖，并单测。
5. 摄像头接入：`getUserMedia` + Hands 推理循环 + 关键点绘制。
6. 界面：牌扇、抽牌动画、结果卡、历史记录、响应式样式。
7. 降级交互：鼠标/触摸/键盘完整可用。
8. 测试：单元测试、构建校验、浏览器冒烟验证。
9. 运行：本地 dev server 与打包产物检查。

## 6. 源数据收集

- 语料范围：毛泽东选集文章、会议讲话、题词与诗词中的广为流传语句，共 100 条。
- 每一条记录 `text`、`source`、`excerpt`、`interpretation`、`tags`，并在结果卡中展示出处、原文选段与解读。
- 结果页内置深度解读 Prompt 生成器，用户可一键复制后粘贴到任意 agent 继续对话。
- 数据来源以人民出版社公开出版物、公开题词、公开影像文献的常见表述为准。
- 校对原则：优先使用通行引文；出处不确定时使用宽泛但准确的标注（如"题词（延安时期）"）。
- 后续可扩展：增加"篇目原文上下文"字段、按标签筛牌、来源链接与免责说明。

## 7. 测试方案

- 单元测试：手势引擎（左划、右划、收拢、防误触、状态上报）、语录数据完整性。
- 构建校验：`npm run build` 检查 TS 与打包。
- 手动测试：真机浏览器授权摄像头，验证弱光、近景、远景下识别稳定性。
- 浏览器冒烟：无摄像头时验证牌扇、键盘、结果弹层与历史记录。

## 8. 风险与后续

- MediaPipe 首次加载约 16MB 本地资源，建议后续做模型懒加载与启动进度展示。
- 摄像头场景依赖光线与手部大小；可增加灵敏度设置。
- 语录属于历史文献引文，商用发布前应复核版权与出版授权。
- 可继续接入 TTS 朗读、分享卡片、每日一签等扩展。
